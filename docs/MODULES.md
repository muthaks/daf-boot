# DAF modules: what each one is, and what it becomes

An assessment of every module in the legacy DAF repositories (`reviewmandates/approvalforum`
and `reviewmandates/approvalforumrules`), what it actually does, and the `daf-boot` module that
replaces it.

Read together with [MIGRATION_MAP.md](MIGRATION_MAP.md), which tracks the per-class progress and
is regenerated by `api/tools/migration-map.py`. This file is the *why*; that one is the *state*.

DAF runs as **five deployables** today, and the target keeps that separation rather than
collapsing everything into one service:

| Container | Port | Legacy modules | daf-boot module |
| --- | --- | --- | --- |
| `daf-api` | 40200 | web, service, jdbc, security, model | `api/` |
| `daf-ui` | 40201 | approvalforum-ui | `web/` + `web-daf/` |
| `daf-rules` | 40202 | approvalforumdrools, approvalforumrules-* | `rules/` |
| `daf-socketio` | 40203 | approvalforum-socketio | `socketio/` |
| `daf-docgen` | 40204 | approvalforum-docgen | `docgen/` |
| — | — | approvalforum-soap | `soap/` |
| — | — | approvalforum-proxy | `proxy/` |

---

## 1. The main API — `api/`

**Legacy:** `approvalforum-web`, `approvalforum-service`, `approvalforum-jdbc`,
`approvalforum-security`, `approvalforum-model`.

**What it does.** The whole DAF business application: agenda builder, capture, review, approval
and chair workflows; committee and meeting administration; document handling; conditions and
meeting records; reporting. It exposes nine REST resources, persists through JPA/Hibernate to
`wc_approvalforum` on SQL Server with Flyway migrations and Envers audit tables, and issues its
own JWT role token derived from the caller's AD group membership.

**Stack today.** Java 8, Guice for DI, Guice-persist transactions, JAX-RS resources on RESTEasy
in a Tomcat war, `javax.*` namespace.

**Work required: full rewrite of the edges, business logic unchanged.**

| From | To |
| --- | --- |
| Guice modules and `@Inject` | Spring configuration and DI |
| Guice-persist `@Transactional` | Spring `@Transactional` |
| JAX-RS `@Path`/`@GET`/`@QueryParam` on RESTEasy | Spring MVC `@RestController`/`@GetMapping`/`@RequestParam` |
| JAX-RS `ContainerRequestFilter` auth chain | Spring Security filter chain |
| `javax.persistence`, `javax.inject` | `jakarta.*` |
| JNDI datasource, manual Flyway bootstrap | `spring.datasource`, Boot's Flyway auto-configuration |
| war on Tomcat | executable jar |

Endpoint paths, HTTP verbs, parameter names, request/response shapes and status codes do not
move - `web/` and `web-daf/` must keep working against it unchanged.

---

## 2. Document generation — `docgen/`

**Legacy:** `approvalforum-docgen` (13 classes).

**What it does.** Generates the committee documents and reports. Four endpoints:
`POST /generate`, `POST /generateASB`, `POST /generatePdfForBroaderAfrica`, `GET /ping`.

**Stack today.** **Already Spring Boot** - `Application.java`, `@RestController`, `@Autowired`,
`config/SecurityConfig`, `security/JwtAuthorizationFilter`. Java 8, inherits the `approvalforum`
parent pom.

**Work required: a version upgrade, not a port.** Move to the Spring Boot 4 starter parent,
Java 8 → 25, `javax.*` → `jakarta.*`, and bring the JWT filter in line with the platform's
auth-service token handling. The controller and service code carry over close to as-is.

---

## 3. SOAP endpoint — `soap/`

**Legacy:** `approvalforum-soap` (4 classes, `war` packaging).

**What it does.** The inbound SOAP contract for external systems - `createExternalRequest` and
`cancelExternalRequest`, declared with Spring-WS `@PayloadRoot` against the DAF namespace.

**Stack today.** **Already Spring Boot 2.2.1**, Spring-WS, Java 8, deployed as a war alongside
the main app (`approvalforum-soap.war`).

**Work required: a version upgrade plus a packaging change.** Spring Boot 2.2.1 → 4, Java 8 → 25,
`javax.xml.ws` → `jakarta.xml.ws`, and `war` → executable `jar` (Boot 4 standalone rather than a
Tomcat deployment). The WSDL/XSD contract and the endpoint payload roots stay byte-identical -
external callers must not notice.

---

## 4. Rules engine — `rules/`

**Legacy:** `approvalforumdrools` (its own five sub-modules: `-jdbc`, `-model`, `-security`,
`-service`, `-web`) plus `approvalforumrules-client`, `approvalforumrules-model` and
`approvalforumrules-rest-client`.

**What it does.** The Drools rules service the main API calls to evaluate mandate rules
(`RuleData.drl`), with its own JPA repository over the rules tables and its own JWT security. The
`-client` / `-rest-client` / `-model` modules are the library the API uses to call it.

**Stack today.** Java 8, Guice, JAX-RS, its own `TokenBasedSecurityContext` and filter chain -
structurally a second copy of the main API's stack.

**Work required: a second full rewrite, same transformations as `api/`.** The Spring Security
chain written for `api/` applies here directly. The three client modules fold into `rules/` (or
become a small shared client the API depends on) rather than staying separate artifacts.

---

## 5. Realtime notifications — `socketio/`

**Legacy:** `approvalforum-socketio`.

**What it does.** Pushes realtime notifications to the browser. `express` + `socket.io` 2.x +
`socketio-jwt`, entry point `server.js`.

**Work required: move it across unchanged. It does not become Spring Boot.** Spring has WebSocket
and STOMP support, but the browser client speaks the socket.io protocol, which is not the same
thing - converting the server would force a rewrite of the client too, for no benefit. It keeps
its Node runtime and its own Dockerfile, exactly as it deploys today.

---

## 6. Reverse proxy — `proxy/`

**Legacy:** `approvalforum-proxy` - two nginx configuration files (ssl and non-ssl).

**Work required: none beyond relocation.** Configuration, not code. It moves across and is kept
in step with the platform nginx conventions.

---

## 7. Web UI — `web/` and `web-daf/`

**Legacy:** `approvalforum-ui` (Angular 8).

**What it does.** The DAF user interface: capture, review, approval, chair and the agenda builder.

**Work required: already under way, as platform remotes rather than one app.** `web/` carries the
migrated Agenda Builder; `web-daf/` carries the remaining DAF modules. Both follow
`cat-utils/co-platform/docs/REMOTE-STANDARDS.md` - Angular 22, co-ds components, the five-file
`remote/` contract, no custom CSS. The Angular 8 app is retired module by module as each one
lands in a remote.

---

## Order of work

1. **Spring Security chain in `api/`** - it unblocks compilation there and is reused verbatim by `rules/`.
2. **`approvalforum-model` into `api/dto`** - removes the last dependency on a legacy artifact.
3. **`docgen/` and `soap/`** - cheapest wins; mostly parent pom and Java version.
4. **`rules/`** - the second rewrite.
5. **`socketio/` and `proxy/`** - relocate as-is.
