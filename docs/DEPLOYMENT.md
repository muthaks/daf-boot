# Deploying DAF

How the DAF system is deployed, what each server needs, and what to change when a piece moves to another server. The platform-wide conventions (stack layout, ports, subnets, the deploy tool) are in cat-utils `docs/DEPLOYMENT.md`.

## 1. The pieces

| Piece                                                                    | Repository                             | Deployed as (deploy tool stack)       | DEV server                                    | Reached by                                                                             |
| ------------------------------------------------------------------------ | -------------------------------------- | ------------------------------------- | --------------------------------------------- | -------------------------------------------------------------------------------------- |
| daf-boot: daf-api, daf-rules, daf-docgen, daf-soap                       | daf-boot                               | `daf`                                 | rmb-rbvdvcsdm01 (`backend/daf-boot`)          | the gateway, as `/gateway/daf` (daf-api, port 14736)                                   |
| DAF remote, Agenda Builder remote                                        | credit-platform                        | `daf-remote`, `agenda-builder-remote` | rmb-rbvdvcsdm01                               | the browser, through the platform nginx (`/platform/remotes/...`)                      |
| API gateway                                                              | cat-utils                              | `co-api-gateway`                      | rmb-rbvdvcsdm01                               | the remotes and daf-boot (`https://credit-systems-dev.rmb.co.za/gateway`)              |
| auth-service-boot                                                        | auth-service-boot (stack in cat-utils) | `auth-service-boot`                   | rmb-rbvdvcsdm01                               | the gateway, as `/gateway/auth`                                                        |
| Credit Data Boot (application, counterparty, facility, referencedata, …) | creditdata-boot                        | `creditdata-boot`                     | rmb-rbvdvcsdm01 (moving from rmb-rbvdvwcrm01) | the gateway, as `/gateway/creditdata` (through that server's nginx, ports 14721–14731) |
| mailservice-boot                                                         | mailservice-boot                       | `mailservice`                         | rmb-rbvdvcsdm01                               | the gateway, as `/gateway/mailservice`                                                 |
| Windows SSO servers                                                      | (existing)                             | —                                     | the Credit Risk servers                       | the browser (`AF_SSO_SERVERS`)                                                         |

## 2. Who calls whom

Every call between pieces goes through the gateway, by name, so a piece can move without the others changing code.

| Caller           | Calls                                                                   | Through                                                                                                | Credential                                                    |
| ---------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------- |
| Browser          | Windows SSO server (`userdetail`, `loginpost`)                          | direct, HTTPS                                                                                          | the Windows session                                           |
| Remotes          | daf-api (`/auth/ssoServers`, `/auth/tenant`, `/auth/ssoToken`, the API) | gateway `/daf`                                                                                         | DAF's own role token (from `/auth/ssoToken`)                  |
| daf-api          | auth-service-boot (sign-in, AD users, groups, domains)                  | gateway `/auth` (`AF_AUTHSERVICE_BASE`)                                                                | none (open endpoints)                                         |
| daf-api          | auth-service-boot system tokens                                         | gateway `/auth` (`AF_SYSTEM_TOKEN_URL`)                                                                | DAF's system code + bootstrap client secret                   |
| daf-api          | Credit Data Boot                                                        | gateway `/creditdata/<service>`, `/creditdata/ash/<service>`                                           | a CREDITDATA system token, added to every Credit Data request |
| daf-api          | mailservice-boot                                                        | gateway `/mailservice`                                                                                 | a MAILSERVICE system token                                    |
| Credit Data Boot | auth-service-boot (CREDITDATA signing key, at start-up)                 | gateway `/auth` (`AUTH_SERVICE_URL`)                                                                   | CREDITDATA's bootstrap client secret                          |
| Gateway          | daf-api, auth-service-boot, Credit Data                                 | its upstreams (`DAF_API_HOST`/`DAF_API_PORT`, `AUTH_API_HOST`/`AUTH_API_PORT`, `CREDITDATA_API_NODES`) | —                                                             |

## 3. What each server holds

Each stack's settings live in `env.properties` on its server. A deploy uploads the example as `env.properties.example` and adds keys the server's file lacks; it never changes a value that is already there. A server-specific value therefore has to be set on the server, once.

| Stack               | Setting                                                                                   | Holds                                                                           | Changes when                                               |
| ------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| `daf`               | `AF_AUTHSERVICE_BASE`                                                                     | the gateway's `/auth` (`https://<platform host>/gateway/auth`)                  | the environment changes                                    |
| `daf`               | `AF_*SERVICE_BASE`, `AF_*SERVICE_ASH_BASE` (application, counterparty, facility, refdata) | the gateway's `/creditdata/<service>` and `/creditdata/ash/<service>`           | the environment changes                                    |
| `daf`               | `AF_SYSTEM_TOKEN_URL`, `AF_SYSTEM_CALLER`, `AF_SYSTEM_BOOTSTRAP_CLIENT_SECRET`            | DAF's system sign-in (mail and Credit Data tokens)                              | the environment changes, or DAF's secret is rotated        |
| `daf`               | `AF_SSO_SERVERS`                                                                          | the Windows SSO servers, HTTPS                                                  | the environment changes                                    |
| `daf`               | `AF_LISTMANAGEMENTSERVICE_BASE`, database, CASDM, Lumos, mail settings                    | the environment's services                                                      | the environment changes                                    |
| `daf`               | `DOCKER_SUBNET` (optional), `API_PORT` …                                                  | the stack's network and published ports                                         | the default range or a port is taken on the server         |
| `co-api-gateway`    | `DAF_API_SCHEME`, `DAF_API_HOST`, `DAF_API_PORT`                                          | where daf-api runs                                                              | **daf-boot moves**                                         |
| `co-api-gateway`    | `CREDITDATA_API_NODES`                                                                    | the server(s) whose nginx serves Credit Data                                    | **Credit Data moves or is added**                          |
| `co-api-gateway`    | `AUTH_API_HOST`, `AUTH_API_PORT`                                                          | where auth-service-boot runs                                                    | **auth-service-boot moves**                                |
| `auth-service-boot` | `AUTH_SYSTEM_TOKENS_MAILSERVICE`, `AUTH_SYSTEM_TOKENS_CREDITDATA`                         | the systems allowed those system tokens (`DAF`)                                 | another system needs them                                  |
| `creditdata-boot`   | `AUTH_SERVICE_URL`, `AUTH_SERVICE_BOOTSTRAP_CLIENT_SECRET`                                | how it gets CREDITDATA's signing key; blank = auth-service tokens refused (403) | the environment changes, or CREDITDATA's secret is rotated |
| `creditdata-boot`   | `SERVICES`, `DOCKER_SUBNET`, ports, datasources                                           | which services run, their network, ports and databases                          | the server changes                                         |

A blank value in daf-boot's `env.properties` counts as not set: the built-in default applies. Credit Data Boot, the gateway and auth-service-boot have no such rule; set their values or leave the keys out.

## 4. Deploy order (an environment from scratch)

| #   | Stack                          | Run from         | Command                                                                                          | Check                                                                                                           |
| --- | ------------------------------ | ---------------- | ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| 1   | auth-service-boot              | cat-utils        | `deploy/pam-deploy.sh auth-service-boot <server> -u <you>`                                       | `/gateway/auth/api/v1/auth/ping` → 200                                                                          |
| 2   | Credit Data Boot               | cat-utils        | `deploy/pam-deploy.sh creditdata-boot <server> -u <you>`                                         | counterparty log: `Auth-service token verification key bootstrapped … for system CREDITDATA`                    |
| 3   | mailservice-boot               | mailservice-boot | `deploy/pam-deploy.sh mailservice <server> -u <you>`                                             | its health check                                                                                                |
| 4   | daf-boot                       | daf-boot         | `deploy/pam-deploy.sh daf <server> -u <you>`                                                     | daf-api log: `Credit Data system token for CREDITDATA: from the auth service`                                   |
| 5   | gateway                        | cat-utils        | `deploy/pam-deploy.sh co-api-gateway <server> -u <you>`                                          | `/gateway/daf/actuator/health` → 200; `/gateway/creditdata/counterparty/api/PESearch` without a token → 401/403 |
| 6   | DAF and Agenda Builder remotes | credit-platform  | `deploy/pam-deploy.sh --release <env> <server> -u <you> --only daf-remote,agenda-builder-remote` | the pages open and load data on the first visit                                                                 |

Run each command from that repository's develop checkout: the tool uploads the stack files from the local working tree. Credit Data Boot is deployed from cat-utils (its `creditdata-boot` stack takes the files from a creditdata-boot checkout next to cat-utils, puts the stack in `backend/creditdata-boot` and sets `AUTH_SERVICE_URL` to the environment's gateway); creditdata-boot's own deploy tool only knows the WCRM server. TeamCity must have built the images first (DEV deploys `latest`).

## 5. Moving a piece to another server

| Moving            | On the new server                                                                                                                                                                                          | Elsewhere                                                                                                                                                                                   |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| daf-boot          | Add a deploy target for the server; copy `env.properties` from the old server; set `DOCKER_SUBNET` if the default is taken; deploy `daf`                                                                   | Gateway: `DAF_API_HOST` (and `DAF_API_SCHEME` / `DAF_API_PORT`: HTTPS 443 through that server's nginx when it is not the gateway's own server); restart the gateway                         |
| Credit Data Boot  | Copy `env.properties`, including `AUTH_SERVICE_BOOTSTRAP_CLIENT_SECRET`; set `DOCKER_SUBNET` if `172.31.100.128/28` is taken; the server's nginx needs the platform snippet (`/creditdata/api/<service>/`) | Gateway: `CREDITDATA_API_NODES` to the new server's HTTPS front door; restart the gateway. daf-boot: nothing                                                                                |
| auth-service-boot | Deploy it with the same database and master key                                                                                                                                                            | Gateway: `AUTH_API_HOST` / `AUTH_API_PORT`; restart the gateway. daf-boot and Credit Data: nothing (they call `/gateway/auth`)                                                              |
| The gateway       | Deploy `co-api-gateway` and the platform nginx's `/gateway/` location                                                                                                                                      | daf-boot: `AF_AUTHSERVICE_BASE`, `AF_SYSTEM_TOKEN_URL`, `AF_MAILSERVICE_BASE`, `AF_*SERVICE_BASE` if the host name changes; Credit Data: `AUTH_SERVICE_URL`; the remotes' `DAF_WEB_API_URL` |
| A new environment | Everything in section 4, with that environment's values                                                                                                                                                    | Register the systems (DAF, CREDITDATA, MAILSERVICE) on that environment's auth service and note their bootstrap secrets                                                                     |

After a move, stop the old copy and rename or remove its folder, so it is not started again by mistake.

## 6. Problems seen, and their causes

| Symptom                                                             | Cause                                                                                   | Fix                                                                      |
| ------------------------------------------------------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `invalid reference format` on deploy                                | `DOCKER_REGISTRY` unset                                                                 | daf-boot's `latest.sh` now defaults it; other stacks read it from `.env` |
| `Pool overlaps with other one on this address space`                | the stack's subnet is already used on that server (often an old copy of the same stack) | stop the old copy, or set `DOCKER_SUBNET` to a free range                |
| Gateway 404 on `/gateway/daf/...`                                   | the gateway still points at another DAF, or runs an older image without the route       | `DAF_API_*` in the gateway's `env.properties`; redeploy the gateway      |
| Gateway 502                                                         | the upstream (daf-api, Credit Data) is not running on the server the gateway points at  | start it, or correct the gateway's upstream setting                      |
| Remote shows "session not accepted" (401), `/auth/ssoServers` empty | `AF_SSO_SERVERS` blank                                                                  | set it (HTTPS list)                                                      |
| `/auth/ssoToken` 500, `WeakKeyException`                            | `authentication.jwt.secret=` blank                                                      | remove the line (built-in key) or set a key of 32+ characters            |
| Credit Data 403 with a CREDITDATA token                             | Credit Data Boot's `AUTH_SERVICE_BOOTSTRAP_CLIENT_SECRET` blank                         | set it, restart Credit Data Boot                                         |
| `manifest unknown` on pull                                          | the image was never pushed (the module is not on the branch TeamCity built)             | build the branch that has it, or leave that service out of `SERVICES`    |
| `unknown target` from the deploy tool                               | run from the wrong repository (each repository knows only its own stacks and targets)   | run from the repository in section 4                                     |
